# Education Portal user guide

This guide explains how to use the Education Portal, step by step. There is one page per task. Read them in the order below the first time; after that, open the page you need.

The guide is written in English. Arabic and Urdu screens are laid out right to left, so *left* and *right* swap on those screens. Arabic and Urdu translations of this guide are not written yet (a follow-up).

Every example uses invented names and addresses (`Example School`, `ada.example@example.test`). Never type real student, parent or staff data into an example.

## Who this guide is for

- **Master tenant administrators** run the platform: they create schools, set their domains and modules, and approve school requests.
- **School administrators** run one school: they add its campuses, users and roles.
- **Staff, teachers, students and parents** sign in and use the parts of the portal their role allows.

## Reading order

| Order | Page | What it covers |
|---|---|---|
| 1 | [Sign in](sign-in.md) | Signing in on your school's domain, and choosing your own password |
| 2 | [Create a school](create-a-school.md) | Master tenant only: add a school with its first administrator |
| 3 | [Enable modules for a school](enable-modules-for-a-school.md) | Master tenant only: what a school may use |
| 4 | [Add a campus](add-a-campus.md) | Add a campus with its contact details and map location |
| 5 | [Set campus codes](set-campus-codes.md) | The code shown in front of every campus |
| 6 | [Create a role](create-a-role.md) | Roles and the rights they give per module |
| 7 | [Create a user](create-a-user.md) | Add a person, optionally with a sign-in account, and assign campuses and roles |
| 8 | [Whole-school items per campus](whole-school-items-per-campus.md) | Holidays, events and photos that apply to the whole school |

The flow in one line: *school exists, then its modules, then campuses, then roles with their rights, then users, then the user signs in and checks.*

## Status of each page

Each page says where a step is not yet built or not yet checked by running the app. Look for the note **Not verified in the running app** and treat that step as the expected behaviour from the code, not as a confirmed screen.
